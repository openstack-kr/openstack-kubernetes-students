===================
OpenStack 핵심 개념
===================

OpenStack은 서버의 컴퓨팅·네트워크·스토리지를 API로 제공하는
오픈소스 IaaS(Infrastructure as a Service) 플랫폼입니다.
사용자는 프로젝트에 할당된 권한과 자원 한도 안에서 인스턴스와 네트워크 등을
요청합니다. 관리자는 각 서비스를 배포하고 자원·권한·장애를 관리합니다.

주요 서비스
------------------------------------------------------------

.. list-table::
   :header-rows: 1

   * - 서비스
     - 역할
     - 실습에서 이해할 대상
   * - Keystone
     - 인증, 권한과 서비스 카탈로그 제공
     - 토큰, 사용자, 프로젝트, 역할
   * - Nova
     - 인스턴스의 생성·삭제 등 수명주기 관리
     - 컴퓨트 서비스, 인스턴스
   * - Placement
     - 자원 제공자의 용량·사용량과 할당 정보 관리
     - 리소스 제공자, 자원 배치 후보
   * - Glance
     - VM 이미지의 등록·조회·전달
     - 인스턴스 부팅에 사용할 이미지
   * - Neutron
     - 가상 네트워크 연결과 관련 자원 관리
     - 네트워크, 서브넷, 포트, 라우터
   * - Cinder
     - 영구 블록 스토리지 제공
     - 인스턴스에 연결할 볼륨
   * - Swift
     - 객체 스토리지 제공
     - 컨테이너와 객체 단위의 데이터
   * - Horizon
     - OpenStack API를 사용하는 웹 대시보드
     - 웹에서 자원을 조회하고 요청

서비스는 필요한 범위에 따라 선택합니다. 표에 소개한 모든 서비스가
실습에 설치됐다는 뜻은 아니며, 배포 목록은 각 구축 문서에서 확인합니다.
데이터베이스와 메시지 큐 같은 지원 구성요소도 서비스의 상태 저장과
내부 작업 전달에 사용됩니다.

사용자와 자원을 구분하는 용어
------------------------------------------------------------

* **프로젝트** 는 사용자와 자원을 묶는 논리적 범위입니다.
  역할과 정책으로 허용 작업을 정하고, quota로 자원 사용 한도를 제한합니다.
* **이미지** 는 인스턴스 디스크의 바탕이 되는 OS·파일 데이터입니다.
* **Flavor** 는 인스턴스에 요청할 vCPU·메모리·디스크 등의 규격입니다.
* **인스턴스** 는 Nova에 요청하여 생성하는 가상 서버입니다.
* **엔드포인트** 는 클라이언트가 서비스를 호출할 API 주소입니다.
  실제 접근 가능 여부는 주소와 네트워크 경로에 달려 있습니다.

인스턴스 생성의 개념적 흐름
------------------------------------------------------------

.. code-block:: text

   사용자 (Horizon 또는 OpenStack CLI)
     → Keystone 인증
     → Nova에 이미지·Flavor·네트워크를 지정해 생성 요청
     → Nova 스케줄러가 Placement 자원 정보를 활용해 배치 결정
     → Glance 이미지와 Neutron 네트워크 연결 준비
     → 선택된 컴퓨트 노드의 nova-compute와 가상화 드라이버가 VM 실행

이 흐름은 역할을 설명하기 위한 요약입니다. 실제 처리에는 여러 API 호출과
비동기 작업이 포함되며 볼륨 부팅처럼 구성에 따른 추가 과정도 있습니다.

네트워크와 스토리지 읽기
------------------------------------------------------------

Neutron의 네트워크는 가상 연결 영역, 서브넷은 주소 범위와 관련 설정,
포트는 인스턴스 인터페이스 등이 연결되는 지점입니다.
보안 그룹은 포트에 적용하는 허용 규칙을 관리합니다.
Floating IP를 사용하려면 외부 네트워크와 라우팅 등 접근 경로가 준비되어야 합니다.

Glance 이미지, 인스턴스 디스크, Cinder 볼륨은 수명이 서로 다릅니다.
이미지는 부팅의 바탕이고 Cinder 볼륨은 독립적으로 관리하는 블록 장치입니다.
인스턴스 삭제 시 데이터가 유지되는지는 디스크 유형과 삭제 설정에 따라 달라집니다.

이 실습과의 연결
------------------------------------------------------------

OpenStack-Helm은 OpenStack 서비스를 Kubernetes 리소스로 배포합니다.
Kubernetes는 해당 Pod의 실행 상태를 관리하고 OpenStack은 클라우드 자원을 관리합니다.
Keystone 토큰 발급, Nova 서비스 조회, Neutron 네트워크 확인 등은
각 서비스가 동작하는지 확인하는 서로 다른 점검입니다.
