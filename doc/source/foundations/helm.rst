==============
Helm 핵심 개념
==============

OpenStack 을 Kubernetes 위에 올릴 때 반복해서 등장하는 전제 도구입니다.
Helm 은 Kubernetes 애플리케이션의 패키징·배포를 선언적으로 다룹니다. 도구
자체의 상세는 공식 문서로 링크하고, 여기서는 "이 개념이 OpenStack·Kubernetes
결합에서 무엇에 쓰이는가"에 초점을 둡니다.

.. note::

   기여자 작업용 골격입니다. 도구 사용법을 재설명하지 말고, 각 개념이
   OpenStack·Kubernetes 결합의 어디에 쓰이는지(왜 알아야 하는지)를 한 줄로
   유지하세요. 상세는 공식 문서와 해당 섹션으로.

.. warning::

   **아래는 추가한 내용. 검토 후 기존 내용 삭제 필요.**

OpenStack 서비스 하나를 Kubernetes에 배포해도 여러 설정과 리소스가 필요합니다.
Helm은 관련 리소스 템플릿을 차트로 묶고 환경별 값을 적용하여 설치·변경을 관리합니다.

차트, values, 릴리스
------------------------------------------------------------

.. list-table::
   :header-rows: 1

   * - 용어
     - 의미
   * - Chart
     - 관련 Kubernetes 리소스의 템플릿과 기본 설정을 묶은 패키지
   * - values
     - 이미지, 복제본 수, 서비스 설정 등 템플릿에 전달할 값
   * - Release
     - 차트를 특정 이름과 설정으로 설치한 개별 배포
   * - Revision
     - 릴리스의 설치·업데이트 등 변경 이력 번호
   * - Repository
     - 배포할 차트를 찾아 내려받는 저장소

같은 차트를 다른 릴리스 이름과 values로 여러 번 설치할 수 있습니다.
기본 values에 환경별 파일을 덮어써 적용하므로 파일 내용과 적용 순서를 기록합니다.

.. code-block:: text

   차트 템플릿 + 기본 values + 환경별 values
                     ↓ 렌더링
             Kubernetes 매니페스트
                     ↓ 설치·변경
                  Helm 릴리스

OpenStack-Helm과의 관계
------------------------------------------------------------

Helm은 패키지를 처리하는 도구이고, OpenStack-Helm은 OpenStack 서비스와
지원 구성요소를 배포하기 위한 차트와 관련 구성을 제공합니다.
실습에서는 서비스별 차트에 고정한 버전과 환경별 values를 적용합니다.
차트 버전, 컨테이너 이미지 버전, OpenStack 릴리스 이름을 각각 기록합니다.

설치 전에 확인할 것
------------------------------------------------------------

차트 소스의 개별 파일만 읽는 것에 더해 실제 values를 적용한 렌더링 결과를
확인합니다. 공통 템플릿이 생성하는 Service나 Ingress도 이 결과에서 확인할 수 있습니다.
``helm template`` 은 렌더링 확인에 쓰며, 실제 클러스터에서의 실행 성공은
설치 후 별도로 확인합니다.

설치 후 확인할 것
------------------------------------------------------------

.. code-block:: bash

   helm list -n openstack --all
   helm status keystone -n openstack
   helm history keystone -n openstack
   kubectl get pods -n openstack

위 예시는 openstack 네임스페이스에 keystone 릴리스가 있을 때 사용합니다.
Helm 릴리스 상태, Pod 준비 상태, OpenStack API 기능을 함께 확인합니다.
Job이나 다른 서비스의 준비에 의존하는 차트는 배포 순서도 고려해야 합니다.

변경과 복구
------------------------------------------------------------

차트와 values 변경은 릴리스 업데이트로 관리합니다.
롤백 기능은 이전 릴리스 구성으로 돌아가는 데 쓰이지만,
DB 스키마 변경이나 외부 데이터까지 자동으로 되돌린다고 가정해서는 안 됩니다.
데이터 복구 계획은 해당 서비스의 저장 방식과 변경 절차에 맞춰 준비합니다.
