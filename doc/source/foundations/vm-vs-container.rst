VM과 컨테이너의 실행 구조
------------------------------------------------------------

가상 머신(Virtual Machine, VM)은 가상의 CPU·메모리·디스크·네트워크 장치를
제공받고 그 안에서 별도의 운영체제와 커널을 실행합니다.
QEMU는 가상 장치를 제공하고, Linux의 KVM은 지원되는 환경에서
CPU의 하드웨어 가상화 기능을 사용하도록 돕습니다.
libvirt는 이런 VM과 가상 네트워크·디스크를 관리하는 API를 제공합니다.

일반적인 Linux 컨테이너는 실행 노드의 커널을 공유합니다.
namespaces로 프로세스·네트워크 등의 보이는 범위를 나누고,
cgroups로 CPU·메모리 같은 자원 사용량을 제어합니다.
이미지에는 애플리케이션과 실행에 필요한 파일을 담습니다.

.. list-table::
   :header-rows: 1

   * - 구분
     - VM
     - 일반적인 Linux 컨테이너
   * - 커널
     - 게스트 운영체제의 커널을 별도로 실행
     - 실행 노드의 커널 공유
   * - 격리 경계
     - 가상 하드웨어와 하이퍼바이저 경계
     - 프로세스 격리와 커널 보안 기능
   * - 시작 과정
     - 게스트 OS 부팅 후 서비스 실행
     - 이미지 준비 후 애플리케이션 프로세스 시작
   * - 자원 부담
     - 게스트 OS를 위한 메모리·디스크 필요
     - 일반적으로 시작과 메모리 부담이 작음
   * - 관리 도구 예
     - libvirt, OpenStack Nova
     - containerd, Kubernetes
   * - 이미지 예
     - 게스트 OS를 담은 qcow2 디스크 이미지
     - 애플리케이션 파일을 담은 컨테이너 이미지

시작 시간과 성능은 이미지 크기, 캐시, 자원 할당, 저장장치에 따라 달라집니다.
VM과 컨테이너 모두 호스트 및 실행 환경의 보안 설정이 중요합니다.

실습에서 등장하는 두 종류의 VM
------------------------------------------------------------

이 실습은 먼저 베어메탈 서버에 Kubernetes용 노드 VM을 만듭니다.
그 위에서 OpenStack 서비스를 컨테이너로 실행합니다.
이후 OpenStack에 요청해 만드는 사용자 인스턴스는 별도의 자원입니다.

.. code-block:: text

   베어메탈 서버
     └─ libvirt + QEMU/KVM
         └─ 노드 VM 4대 (cp, ctrl-worker, compute-1, compute-2)
             ├─ Kubernetes가 관리하는 OpenStack 서비스 Pod
             └─ 컴퓨트 노드에서 Nova/libvirt가 관리하는 사용자 VM

노드 VM 안에서 사용자 VM을 실행하면 가상화 계층이 중첩됩니다.
내부 VM의 KVM 가속 사용 여부는 중첩 가상화 지원과 설정에 달려 있습니다.
수동 구축 초기 기록에서는 Nova의 ``virt_type=qemu`` 를 사용했습니다.
실제 인스턴스 실행 결과는 해당 실습 단계의 기록으로 확인합니다.

Control Plane과 Data Plane
------------------------------------------------------------

컨트롤 플레인은 요청을 받고 상태를 저장하며 자원의 배치·생성을 결정합니다.
데이터 플레인은 사용자 작업을 실행하거나 실제 패킷·데이터를 처리합니다.
이 구분은 역할을 설명하며 반드시 물리 서버가 분리되어 있다는 뜻은 아닙니다.

.. code-block:: text

   Kubernetes API와 컨트롤러
     └─ OpenStack API·에이전트 등의 Pod 배치와 실행 상태 관리

   사용자 → OpenStack API → 스케줄러·컴퓨트 서비스
                               └─ 사용자 VM 실행
                                   └─ 실제 애플리케이션 트래픽 처리

Nova는 VM 수명주기를 관리하는 OpenStack 서비스입니다.
일반적인 OpenStack-Helm 구성에서 사용자 VM은 Nova/libvirt가 관리하며,
OpenStack 서비스를 실행하는 Pod와는 관리 단위가 다릅니다.

격리를 강화하는 컨테이너 실행 방식
------------------------------------------------------------

gVisor는 사용자 공간의 애플리케이션 커널을 통해 시스템 호출을 처리하여
호스트 커널과의 직접 접점을 줄입니다. Kata Containers는 경량 VM을 활용해
컨테이너 워크로드에 별도 커널과 하드웨어 가상화 경계를 제공합니다.
호환성, 자원 사용량, 장치 접근 요구를 함께 고려해야 하는 실행 방식입니다.
이 두 방식은 여기서 비교를 위한 개념으로 소개합니다.
