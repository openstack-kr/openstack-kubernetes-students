실습 환경과 구축 범위
========================

호스트는 VM 네 대를 실행하는 물리 서버입니다. 노드는 Kubernetes에 참여하는 서버이며,
이 실습에서는 VM 한 대가 노드 하나가 됩니다. 물리 서버에 운영체제를 직접 설치한
환경을 베어메탈이라고 합니다.

``cp`` 는 클러스터의 상태를 관리하는 컨트롤 플레인입니다. etcd는 Kubernetes의
설정과 상태 정보를 저장합니다. 나머지 노드는 서비스를 실행하는 워커로 사용합니다.
``ctrl-worker`` 는 이름에 ctrl이 있지만 Kubernetes 관리 노드인 cp와 다릅니다.
OpenStack의 인증·이미지·API 등 제어 서비스를 배치할 워커입니다.

표의 vCPU는 VM에 배정한 가상 CPU 수입니다. GiB는 메모리 용량 단위이며,
디스크의 GB와 같은 표기로 취급하지 않습니다. 아래 수치는 당시 기록값을 유지했습니다.


호스트는 Ubuntu 24.04.1을 설치한 서버입니다. CPU는 Intel Xeon Gold 6262(2소켓, 96스레드),
메모리는 125 GiB, SSD는 약 465.8 GB였습니다. 호스트에는 ``lab`` 계정으로, VM에는 ``kit`` 계정으로 접속했습니다.

.. list-table:: 노드별 역할과 할당량
   :header-rows: 1

   * - 노드
     - 역할
     - IP
     - vCPU / 메모리 / 디스크
   * - cp
     - Kubernetes 컨트롤 플레인과 etcd
     - 192.168.100.10
     - 4 / 16 GiB / 60 GB
   * - ctrl-worker
     - OpenStack 제어 서비스
     - 192.168.100.11
     - 16 / 32 GiB / 120 GB
   * - compute-1
     - OpenStack 컴퓨트 서비스
     - 192.168.100.21
     - 10 / 32 GiB / 80 GB
   * - compute-2
     - OpenStack 컴퓨트 서비스
     - 192.168.100.22
     - 10 / 32 GiB / 80 GB

Terraform과 libvirt로 VM을 만들고, Ansible로 노드 설정을 맞췄습니다.
Kubespray로 Kubernetes를 설치한 뒤 Helm으로 OpenStack 서비스를 배포했습니다.
2026년 11월 1일 배포를 마쳤고, 11월 2일에 서비스 상태와 API 응답을 확인했습니다.

이번 기록의 범위는 단일 호스트에서 수행한 수동 구축입니다. 사용자 인스턴스 부팅, Floating IP,
호스트 장애 복구, 새 서버에서의 반복 구축은 별도 검증 항목입니다. 당시 기록과 현재 자동화 구현은 별개입니다. 현재 키트의 실행 방법은 :doc:`../kit/index` 에서 확인합니다.
