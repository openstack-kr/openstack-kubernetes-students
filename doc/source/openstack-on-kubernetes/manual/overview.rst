실습 환경과 구축 범위
========================

호스트는 VM 네 대를 실행하는 물리 서버입니다. 노드는 Kubernetes에 참여하는 서버이며,
이 실습에서는 VM 한 대가 노드 하나가 됩니다. 물리 서버에 운영체제를 직접 설치한
환경을 베어메탈이라고 합니다.

``cp`` 는 클러스터의 상태를 관리하는 컨트롤 플레인입니다. etcd는 Kubernetes의
설정과 상태 정보를 저장합니다. 나머지 노드는 서비스를 실행하는 워커로 사용합니다.
``ctrl-worker`` 는 이름에 ctrl이 있지만 Kubernetes 관리 노드인 cp와 다릅니다.
OpenStack의 인증·이미지·API 등 제어 서비스를 배치할 워커입니다.

표의 vCPU는 VM에 배정한 가상 CPU 수입니다. GiB는 메모리 용량 단위이며,
디스크의 GB와 같은 표기로 취급하지 않습니다. 아래 수치는 당시 기록값을 유지했습니다.


호스트는 Ubuntu 24.04.1을 설치한 서버입니다. CPU는 Intel Xeon Gold 6262(2소켓, 96스레드),
메모리는 125 GiB, SSD는 약 465.8 GB였습니다. 호스트에는 ``lab`` 계정으로, VM에는 ``kit`` 계정으로 접속했습니다.

.. list-table:: 노드별 역할과 할당량
   :header-rows: 1

   * - 노드
     - 역할
     - IP
     - vCPU / 메모리 / 디스크
   * - cp
     - Kubernetes 컨트롤 플레인과 etcd
     - 192.168.100.10
     - 4 / 16 GiB / 60 GB
   * - ctrl-worker
     - OpenStack 제어 서비스
     - 192.168.100.11
     - 16 / 32 GiB / 120 GB
   * - compute-1
     - OpenStack 컴퓨트 서비스
     - 192.168.100.21
     - 10 / 32 GiB / 80 GB
   * - compute-2
     - OpenStack 컴퓨트 서비스
     - 192.168.100.22
     - 10 / 32 GiB / 80 GB

Terraform과 libvirt로 VM을 만들고, Ansible로 노드 설정을 맞췄습니다.
Kubespray로 Kubernetes를 설치한 뒤 Helm으로 OpenStack 서비스를 배포했습니다.
2026년 11월 1일 배포를 마쳤고, 11월 2일에 서비스 상태와 API 응답을 확인했습니다.

이번 기록의 범위는 단일 호스트에서 수행한 수동 구축입니다.
11월 3~4일에는 Horizon을 추가 설치하고, CLI로 만든 ``demo-vm1`` 과
Horizon에서 만든 ``demo-vm2`` 의 실행을 확인했습니다.
``demo-vm1`` 은 Neutron VXLAN 포트를 수정한 뒤 내부 DHCP 임대도 확인했습니다.
구체적인 절차와 결과는 :doc:`ch7_horizon` 에 정리했습니다.

최종 확인 범위
------------------------------------------------------------------------------------------

* 11월 1~2일: Helm 릴리스 11개와 서비스 등록·개별 API 동작 확인
* 11월 3~4일: Horizon을 포함한 릴리스 12개, 인스턴스 두 대 실행과 내부 DHCP 확인
* 11월 4일: 오래된 DNS 설정을 가진 API Pod 교체 후 서비스 검사 3회 통과

Nova의 사용자 인스턴스는 ``virt_type=qemu`` 로 실행했습니다.
처음 네 대의 노드 VM을 만드는 호스트 가상화 방식과 구분하며,
사용자 인스턴스의 중첩 KVM 가속을 검증한 것으로 해석하지 않습니다.
MetalLB와 외부 브리지 ``br-ex`` 는 구성하지 않았습니다.

Floating IP 외부 통신, 인스턴스 콘솔 직접 로그인, 호스트 장애 복구,
새 서버 반복 구축은 아직 확인하지 않았습니다. DNS 장애 조치 후 30분 안정성 결과도
원본 기록에 채워져 있지 않습니다. 당시 수동 구축 결과와 현재 자동화 구현은 별개입니다.
키트의 실행 방법은 :doc:`../kit/index` 에서 확인합니다.
