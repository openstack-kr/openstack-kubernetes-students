부록 C. 진단 로그와 재현 검증
==========================================================================================

로그와 재현 검증의 의미
------------------------------------------------------------------------------------------

로그는 프로그램이 실행 과정과 오류를 남긴 기록입니다.
재현 검증은 새 환경에서 같은 절차를 실행하여 같은 결과가 나오는지 확인하는 작업입니다.
한 서버에서 한 번 성공한 결과와 새 서버에서도 반복할 수 있다는 결론은 구분합니다.
이 부록의 명령은 상태를 확인하는 용도이며 오류를 자동으로 고치지는 않습니다.


오류를 수정하기 전에 발생 시각, 실행한 명령, 오류 메시지, 대상 노드와 버전을 함께 기록합니다.
VM 시작 실패는 :doc:`ch8_troubleshooting` 의 권한·AppArmor 점검을, 파드 시작 실패는 아래 조회를 먼저 사용합니다.

.. code-block:: bash

   kubectl get pods -n openstack -o wide
   kubectl get events -n openstack --sort-by=.metadata.creationTimestamp
   helm list -n openstack --all

문제가 발생한 파드의 이벤트와 해당 컨테이너 로그를 확인해 실패 시각과 대조합니다.
공유할 로그에서는 공인 IP, 토큰, 비밀번호와 개인키를 제거합니다.

새 서버에서 확인할 항목
------------------------------------------------------------------------------------------

#. 동일한 OS와 도구 버전으로 시작하고, 이전에 적용한 AppArmor 규칙이나 수동 설정이 남아 있는지 기록합니다.
#. 0~7단계를 순서대로 실행합니다. 각 단계의 시작·종료 시각, 성공 여부, 추가로 입력한 명령, 로그 파일을 남깁니다.
#. 실패한 단계는 증상·근거·조치·조치 후 결과로 정리합니다. 문서를 고친 뒤 새 환경에서 다시 확인합니다.

새 서버 재현, 재부팅 후 동작, AppArmor 규칙 유무에 따른 비교는 아직 완료하지 않았습니다.
수동 구축 초안에 언급된 진단 스크립트는 파일과 실행 결과를 확보한 뒤 재현 절차에 포함합니다.
현재 자동화 키트에 있는 점검·검증 스크립트의 설명은 :doc:`../kit/verification` 에서 확인합니다.
7단계 이후 추가로 남길 기록
------------------------------------------------------------------------------------------

Horizon 로그인과 인스턴스 생성 결과는 :doc:`ch7_horizon` 에 정리했습니다.
같은 결과를 확인할 때 인스턴스 상태뿐 아니라 부팅 로그와 DHCP 임대를 함께 남깁니다.
Floating IP 외부 통신과 콘솔 직접 로그인은 별도 시험으로 기록합니다.

DNS 문제는 대상 Pod의 생성 시각과 내부 ``/etc/resolv.conf``, 서비스 이름 해석 결과,
관련 API 로그를 함께 수집합니다. Pod를 교체했다면 새 Pod에서도 다시 확인합니다.
VXLAN 문제는 실제 UDP 포트, OVS 인터페이스 오류와 변경 후 DHCP 로그를 남깁니다.

11월 4일 서비스 검사 3회 통과는 장애 조치 후 결과입니다. 새 환경 반복 구축,
재부팅 복구, 30분 안정성 검증을 대신하는 결과로 사용하지 않습니다.
