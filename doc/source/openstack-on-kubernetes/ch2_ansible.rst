2단계. 노드 사전 설정 (Ansible)
===============================

이 단계가 하는 일
-----------------

1단계에서 만든 VM 4대에 Kubernetes를 설치하기 전에 **공통 준비 작업을 한 번에 적용하는 단계**\ 입니다. 이삿짐을 풀기 전에 네 개의 방 모두에 같은 전기와 수도 설비를 갖추는 일과 같습니다.

- **Ansible** 은 여러 서버에 같은 설정을 한꺼번에 적용하는 도구입니다. "이 서버들에 이 작업들을 순서대로 해라"를 적은 파일(**플레이북**)을 읽어서 SSH로 각 VM에 작업을 시킵니다.
- 3단계의 Kubespray도 Ansible로 동작하므로, 여기서 Ansible이 4대에 정상 접속되는지 먼저 확인하는 의미도 있습니다.

적용하는 설정은 다음과 같습니다.

+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| 작업                                           | 왜 필요한가                                                                                                 |
+================================================+=============================================================================================================+
| swap 끄기                                      | Kubernetes가 요구하는 조건입니다. (클라우드 이미지는 기본적으로 swap이 꺼져 있어 이미 0인 경우가 많습니다.) |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| 커널 모듈 ``overlay``, ``br_netfilter`` 올리기 | 컨테이너 파일 시스템과 컨테이너 네트워크가 동작하는 데 필요합니다.                                          |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| IP 포워딩 켜기 (``net.ipv4.ip_forward=1``)     | 컨테이너(파드) 사이의 통신이 노드를 통과해 전달되게 합니다.                                                 |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| ``/etc/hosts`` 에 노드 이름 등록               | 노드끼리 ``compute-1`` 같은 이름으로 서로를 부를 수 있게 합니다.                                            |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| 시간 동기화 확인                               | 인증서 유효 시간 때문에 노드들의 시계가 맞아야 합니다.                                                      |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+
| 기본 패키지 설치                               | 이후 단계의 도구가 쓰는 패키지입니다.                                                                       |
+------------------------------------------------+-------------------------------------------------------------------------------------------------------------+

선행 조건
---------

- 1단계 완료 (VM 4대 ``running``, SSH 접속 가능)

- Ansible이 설치된 가상환경이 켜져 있을 것

  .. code:: bash

     source ~/venv-kubespray/bin/activate     # 프롬프트 앞에 (venv-kubespray) 가 붙음

.. warning::

   **터미널을 새로 열거나 tmux에서 다시 접속했다면 위 ``activate`` 를 다시 하세요.** 하지 않으면 ``ansible: command not found`` 가 납니다.

준비한 파일
-----------

모든 파일은 ``~/openinfra-lab-kit/ansible`` 에 둡니다.

.. _inventoryini--노드-목록과-역할:

**inventory.ini** : 노드 목록과 역할
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

3단계의 Kubespray가 같은 그룹 이름을 쓰므로 **이름을 그대로** 맞춥니다.

.. code:: ini

   [kube_control_plane]
   cp          ansible_host=192.168.100.10 ip=192.168.100.10 access_ip=192.168.100.10

   [etcd]
   cp

   [kube_node]
   ctrl-worker ansible_host=192.168.100.11 ip=192.168.100.11 access_ip=192.168.100.11
   compute-1   ansible_host=192.168.100.21 ip=192.168.100.21 access_ip=192.168.100.21
   compute-2   ansible_host=192.168.100.22 ip=192.168.100.22 access_ip=192.168.100.22

   [k8s_cluster:children]
   kube_control_plane
   kube_node

- ``ansible_host`` 는 접속할 주소입니다.
- ``ip`` 는 그 노드가 자기 서비스를 열 때 쓰는 주소, ``access_ip`` 는 다른 노드가 그 노드에 접속할 때 쓰는 주소입니다. 아래 "노드 자기 이름이 127.0.1.1로 풀림" 때문에 미리 명시합니다.

.. _ansiblecfg--접속-설정:

**ansible.cfg** : 접속 설정
~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code:: ini

   [defaults]
   inventory = inventory.ini
   remote_user = kit
   private_key_file = ~/.ssh/id_vm_ed25519
   host_key_checking = False
   interpreter_python = auto_silent
   retry_files_enabled = False

.. warning::

   ``host_key_checking = False`` 는 VM을 지우고 같은 IP로 다시 만들 때 생기는 "호스트 키가 바뀌었다" 오류를 피하려는 **실습 환경 전용 설정**\ 입니다. 운영 환경에서는 쓰지 마세요.

단계별로 따라 하기
------------------

.. _1-접속-확인:

1. 접속 확인
~~~~~~~~~~~~

.. code:: bash

   cd ~/openinfra-lab-kit/ansible
   # STAGE 2
   # MANUAL 2
   ansible --version | head -1        # ansible [core 2.18.19]
   ansible all -m ping                # 4대 모두 SUCCESS / pong

.. _2-적용-전-상태-보기-읽기-전용:

2. 적용 전 상태 보기 (읽기 전용)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code:: bash

   ansible all -m shell -a 'echo swap줄수=$(swapon --show | wc -l) 모듈=$(lsmod | grep -cE "overlay|br_netfilter") ip_forward=$(sysctl -n net.ipv4.ip_forward) 시간=$(timedatectl show -p NTPSynchronized --value)'

이 가이드의 VM에서는 ``swap줄수=0 모듈=0 ip_forward=0 시간=yes`` 가 4대 모두 같게 나왔습니다. swap은 이미 꺼져 있었고, 모듈과 ``ip_forward`` 는 적용이 필요한 상태였습니다.

.. _3-플레이북-적용:

3. 플레이북 적용
~~~~~~~~~~~~~~~~

.. code:: bash

   ansible-playbook prepare-nodes.yml
   ansible-playbook prepare-nodes.yml      # 한 번 더 실행

끝에 나오는 **PLAY RECAP** 에서 4대 모두 ``failed=0``, ``unreachable=0`` 이어야 합니다. **두 번째 실행은 ``changed=0`` 이 정상입니다.** 이미 원하는 상태라서 바꿀 것이 없다는 뜻이며, "몇 번 실행해도 결과가 같다"(멱등성)를 확인하는 것입니다.

.. _4-적용-결과-확인:

4. 적용 결과 확인
~~~~~~~~~~~~~~~~~

.. code:: bash

   ansible all -m shell -a 'echo swap줄수=$(swapon --show | wc -l) 모듈=$(lsmod | grep -cE "overlay|br_netfilter") ip_forward=$(sysctl -n net.ipv4.ip_forward) 시간=$(timedatectl show -p NTPSynchronized --value) hosts=$(grep -c "192.168.100" /etc/hosts)'
   ansible all -m shell -a 'getent hosts compute-1 | head -1'

기대 결과
---------

+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| 항목                        | 적용 전 | 적용 후                     | 비고                                                                          |
+=============================+=========+=============================+===============================================================================+
| swap 줄 수                  | 0       | 0                           | 이미 꺼져 있음                                                                |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| 커널 모듈 줄 수             | 0       | 3                           | ``lsmod`` 의 ``bridge`` 줄에도 ``br_netfilter`` 가 표시되어 3으로 보임 (추정) |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| ``ip_forward``              | 0       | 1                           |                                                                               |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| 시간 동기화                 | yes     | yes                         |                                                                               |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| ``/etc/hosts`` 노드 주소 줄 | 0       | 4                           | 4대 모두                                                                      |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+
| 플레이북 재실행             |         | ``ok=9 changed=0 failed=0`` | 4대 모두                                                                      |
+-----------------------------+---------+-----------------------------+-------------------------------------------------------------------------------+

이 단계에서 겪은 오류와 주의사항
--------------------------------

.. note::

   **``FAILED`` 라고 나왔지만 실제 실패가 아닌 경우가 있습니다.** ``ansible all -m shell`` 안에서 ``grep -c`` 가 "일치하는 줄이 0개"일 때 종료 코드 1을 돌려주므로, Ansible이 ``rc=1`` 을 실패로 표시합니다. 출력 자체가 정상이면 무시해도 됩니다. 또한 ``shell`` 모듈은 결과와 상관없이 항상 ``CHANGED`` 로 표시합니다. 오류가 아닙니다.

.. note::

   **노드 자기 이름이 ``127.0.1.1`` 로 풀립니다.** ``compute-1`` 에서 ``compute-1`` 을 물으면 자기 자신을 가리키는 루프백 주소(``127.0.1.1``)가 나옵니다. cloud-init이 만드는 ``127.0.1.1 <호스트명>`` 기본 줄이 우리가 넣은 노드 주소 줄보다 위에 있어서 먼저 일치하는 줄이 선택된 것입니다. 오류는 아니지만 Kubernetes 도구가 "내 이름의 IP"를 호스트명으로 찾으면 루프백 주소를 얻을 수 있어서, **인벤토리에 ``ip`` 와 ``access_ip`` 를 직접 적어** 예방했습니다. (3단계에서 노드 내부 IP가 모두 ``192.168.100.x`` 로 잡혀 문제가 없었습니다.)

.. note::

   **VM의 시간 서비스는 호스트와 다릅니다.** 호스트는 ``chrony`` 와 국내 시간 서버, VM은 Ubuntu 기본인 ``systemd-timesyncd`` 와 ``ntp.ubuntu.com`` 을 씁니다. 둘 다 정확한 시각에 맞추므로 문제는 없습니다. 다만 VM도 외부 NTP(UDP 123)를 쓰므로 **이 키트는 UDP 123이 허용된 환경을 전제로 합니다.** (규칙을 등록한 뒤에 VM을 만들었기 때문에, 규칙이 없을 때 VM이 실제로 막히는지는 확인하지 못했습니다.)

.. note::

   - 인벤토리를 고친 뒤에는 반드시 ``ansible all -m ping`` 으로 접속이 그대로 되는지 확인하세요.
   - 첫 번째 실행의 출력은 기록하지 못했습니다. 다음에는 ``ansible-playbook ... | tee ~/logs/prepare-nodes-1.txt`` 로 남기세요.
   - 인벤토리, 설정 파일 편집은 "변수 파일 편집"이라 수동 명령 수 집계에서 제외합니다.
